# ADR-019：秘書桌面——01 分頁成為真正的首頁

- 狀態：Accepted（2026-09-05 實作）
- 關聯：[ADR-007](ADR-007-proposal-only-secretary.md) proposal-only、[ADR-008](ADR-008-gated-agent-executor.md) 批准與收據、[ADR-012](ADR-012-secretary-memory.md) 記憶區與每日工作誌、[ADR-017](ADR-017-pattern-aware-proposals.md) 模式感知、[ADR-018](ADR-018-declared-profile.md) 宣告式個人檔案、問候卡（ROADMAP §11，2026-09-04）

## Context

個性化的前兩步讓秘書開始**用**它記得的東西（ADR-017）並**聽**你說在乎什麼（ADR-018）。但介面還是儀表板：六個分頁、三十幾個面板。01 已經往對的方向走（三欄、今日行動、問候卡、記憶區），使用者仍然要「去某個面板找某件事」——提案清單一次列六張、記憶區一次列六十則、上次做到哪藏在清單最上方。

一個秘書的首頁應該是：**大部分時候待在 01 就夠，其他分頁是詳情。** 這件事有一個可量測的指標：你一天要離開 01 幾次。

## Decision

### D1 由秘書決定該顯示什麼，規則是確定性的

`core/secretary_home.py` 的 `build_home()` 只**重新排列既有的唯讀資料**，挑出三樣東西：

| 槽位 | 規則 | 來源 |
| :-- | :-- | :-- |
| **焦點**（一張） | 提案引擎排序後第一張**關於你的工作**的提案——分數已含 mute／snooze、ADR-017 習慣加權、ADR-018 你宣告的優先。OmniContext 自身的設定提醒（extension 沒 heartbeat、秘書沒有每日排程）留在完整清單，只在沒有別的可看時才佔焦點——否則「驗證 Extension」會以 1.0 分永久占住首頁 | `build_action_proposals` ＋ `attach_execution_actions`（executor 開著才有批准按鈕） |
| **記得**（一則） | 依固定順序：與焦點專案有關的決定／筆記 → 最近一天的工作誌（日層、未過期）→ 你釘選的 → 你最近記下的；挑不到就如實說沒有 | `secretary_notes` |
| **上次做到哪**＋行事曆一句＋個人檔案一行 | 原樣 | `build_today_view`、`load_profile` |

順序是刻意的：先給「你接下來要動的那件事」相關的決定（最可能改變你現在的動作），再給「你昨天做了什麼」，再給你自己釘起來的，最後才是最新的一則。每張卡都寫「為什麼是現在」「為什麼挑這則」。

**不用 LLM 挑。** 這與 ADR-016／017 拒絕的理由一致：秘書「決定顯示什麼」必須可解釋、可測、可預期；LLM 挑的卡片會讓使用者無從理解為什麼今天是這張。

### D2 完整清單降為詳情，其他分頁是更深的詳情

- 01 左欄變成：問候卡 → **秘書桌面** → 「TODAY · 全部提案」與「記憶區」兩個**預設收合**的 `<details>`（展開狀態記在 localStorage，與其他可收合面板同一套機制）。
- 桌面底部一列**詳情 chip**：全部提案（N）、記憶區（N）、進行中專案（N）展開對應面板或跳到對應分頁；Git 同步中心、知識庫、摘要與統計直接跳分頁。計數來自既有唯讀資料。
- 沒有任何面板被移除；`#today-resume`（上次做到哪，含接續／Handoff 按鈕）只是搬進桌面。

### D3 對話優先：卡片是進入對話的入口

每張卡有「💬 問秘書」：把一句帶脈絡的問題**預填**到交辦框（「關於『uavMonitor 落後遠端 2 個 commit』：遠端有新 commit。我現在該怎麼處理？」），**不自動送出**。使用者看到卡片、一鍵開始對話，對話仍走同一條 RAG＋記憶區管線。

考慮過「窄螢幕把對話欄排到最前面」：拒絕。空的對話框在手機上會佔掉第一屏，反而把桌面推到下面；對話優先的正確形狀是「每張卡都能一鍵變成一句話」。

### D4 可量測的指標：一天離開 01 幾次

`initTabs` 在使用者從 01 切到其他分頁時計一次，依日期存在 localStorage（只留 14 天），桌面底部顯示「今天離開首頁 N 次 · 昨天 M 次」。**只算這個瀏覽器的分頁切換**，不進資料庫、不送後端——它是評估這個 ADR 有沒有達到目的的尺，不是新的採集面。

### D5 誠實的收據與失敗隔離

`GET /api/v1/secretary/home` 唯讀；回應帶 `sections`（focus／today／memory／profile 各自 ok 或 `error:<Type>`）、`focus.basis`、`memory_pick.why_this`、`claim_boundary`。一節壞了其他節照出，徽章由 RULES 變 PARTIAL 並列出壞掉的節。桌面讀不到時，下方詳情面板仍完整可用。

### D6 驗收 A18

`docs/TODO.md` A18 與 `core/acceptance.py` `_check_a18`：機器只回報桌面現在挑出什麼、哪一節壞了；「焦點與記得是不是你會挑的、離開首頁的次數幾天後有沒有變少」由人眼確認。

## Alternatives considered

- **用 LLM 從記憶區與提案「寫一段今天的重點」**：拒絕（見 D1）。
- **重寫 01 為單欄對話介面、所有面板變成對話指令**：拒絕。既有面板（批准按鈕、snooze、記憶區表單、排程按鈕）承載 ADR-008 的兩道門，改成對話指令會把「批准」變成一句話——那正是 ADR-007／008 不允許的形狀。
- **把離開次數寫進 usage analytics**：延後。那會新增一種資料類別（介面導覽事件）；先用 localStorage 證明指標有用再談。
- **把 Telegram `/today` 也改用桌面的挑法**：延後。`/today` 已有問候＋上次做到哪＋前三提案，等桌面規則在 01 上證明有用再統一。

## Consequences

- 沒有新 migration、沒有新危險能力、沒有新的隱私面；唯一新增是一個唯讀端點。
- 使用者第一次看到的效果：打開 01 只有問候、一張焦點、一則記得、上次做到哪、一列詳情 chip；清單收起來了但一按就開，展開狀態會記住。
- `tests/test_secretary_home.py` 14 項：焦點＝引擎第一張與計數、系統提醒不佔焦點（只剩系統提醒時才退回）、沒提案不算錯、真引擎接得上、記得的四級順序（焦點專案不分大小寫、專案層工作誌不算日層、早晨包觀察不算工作誌、過期不挑、釘選、最近、偏好不是候選）、組合（resume／行事曆／個人檔案／計數／sections／claim boundary）、今日視圖壞了焦點照出、記得壞了留提示、不寫不呼叫 LLM、API 唯讀、A18 三種狀態。
